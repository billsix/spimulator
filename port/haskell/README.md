# spimulator-haskell: the engine in GHC Haskell

A port of the spimulator engine (the C files in `src/`) to GHC Haskell. It behaves as the C
engine does: the same stdout, stderr and exit status for the same arguments and input. The
teaching mode (`-explain`) is not ported; given `-explain` it says so and exits with status 2.
Rules and status: `tasks/reference/engine-ports-design.md`, `tasks/archive/2026/11/10/engine-port-haskell.md`.

    # [CONTAINER] run it like spimulator; the first run builds it (about 15 seconds)
    port/haskell/spimulator-haskell -f helloworld.s

    # [CONTAINER] build explicitly: plain ghc --make, offline, GHC's own libraries only
    port/haskell/build.sh

    # [CONTAINER] compare with the C engine, case by case
    port/harness/compare_engines.py --reference builddir/spimulator --engine $PWD/port/haskell/spimulator-haskell

    # [CONTAINER] the formatter tests: floats printed as glibc does, atof read as glibc does
    port/haskell/tests/check-format.sh
    port/haskell/tests/check-strtod.sh

    # [HOST] regenerate src/Opcodes.hs and src/OpcodeTypes.hs (with every other
    # language's tables) after include/opcodes.tsv changes; commit the result
    make generate

`spimulator-haskell` is a launcher script: it builds `build/spimulator-haskell` when the binary is
missing or older than a source file, then runs it with exactly the environment it was given (the
engine copies the environment onto the simulated stack, so bash's own additions would move every
stack address). The default exception handler is `src/exceptions.s`, found by walking up from the
binary's directory.

## Where each C file went

| C | Haskell | what it is |
|---|---|---|
| `include/opcodes.tsv` | `src/Opcodes.hs` (generated by `tools/gen_opcodes.py`) | the opcode table, one constructor per row, named like the C token |
| `include/opcode-types.tsv` | `src/OpcodeTypes.hs` (generated) | operand shapes |
| sorted tables in `instruction.c`, `scanner.c` | `src/OpcodeTables.hs` | the lookups, with glibc's `bsearch`, over tables with one row per key |
| `include/instruction.h`, `symbol-table.h` | `src/Types.hs` | instructions, immediates, labels |
| (globals of every file) | `src/State.hs` | the machine: one record of mutable cells |
| `spim.c` (output, errors) | `src/Output.hs` | console IO, `error`, `run_error`, `fatal_error` |
| `include/registers.h`, `raise_exception` | `src/Registers.hs` | register files, CP0, exceptions |
| `instruction.c` (encode/decode) | `src/Instruction.hs` | pure encoding and decoding |
| `memory.c` | `src/Memory.hs` | the five segments, memory-mapped IO |
| `instruction.c` (disassembly), breakpoints | `src/InstFormat.hs` | disassembly, breakpoints, `print_mem` |
| scattered helpers | `src/AsmCommon.hs` | location counters, parse errors, listing events |
| `symbol-table.c` | `src/SymbolTable.hs` | labels and forward references |
| `data.c` | `src/DataSegment.hs` | data directives |
| `instruction.c` (assembling) | `src/Assemble.hs` | instructions into memory, `$at` expansions |
| `ast.c`, `include/ast.h` | `src/Ast.hs` | the syntax tree and its printers (pure) |
| `scanner.c` | `src/Scanner.hs` | tokens |
| `parser.c`, `pseudo-op.c` | `src/Parser.hs` | parser, pseudo-op expansions, emitter |
| `syscall.c` | `src/Syscall.hs` | system calls, exception reports |
| `run.c` | `src/Run.hs` | the fetch-execute loop |
| `display-utils.c` | `src/DisplayUtils.hs` | register and memory displays |
| `spim-utils.c` | `src/SpimUtils.hs` | initialization, loading, the run stack |
| `spim.c` | `src/Main.hs` | the command line and the REPL |
| (printf of floats, atof) | `src/CFormat.hs` | glibc's float formats and `atof`, exactly |

## Conventions

- **Compatibility first, then readability.** Each function names the C function it ports, and
  follows it statement by statement where the order shows in the output (error messages, the
  order things are printed, which of two equal table rows a search finds).
- **Pure where C allows it.** Encoding, decoding, the opcode tables, the AST printers, the float
  formatter and the arithmetic are pure functions. The machine state is one `Spim` record of
  `IORef`s and `IOUArray`s (`src/State.hs`), passed as the first argument, `s`, to everything
  that touches it. The scanner and parser are in `IO` because the C engine's are interleaved with
  the symbol table: whether a word is a keyword or a constant depends on what has been defined
  when it is scanned.
- **Machine integers.** `Int32` for signed registers, `Word32` for addresses and unsigned views,
  conversions with `fromIntegral`; `quot`/`rem` (C truncation), never `div`/`mod`, on machine
  values. `Float` is IEEE single, so `add.s` rounds as C does; bit patterns move with
  `castWord32ToFloat` and friends. A float-to-int conversion of NaN or an out-of-range value gives
  `0x80000000`, as on x86 (`toInt32` in `src/Run.hs`).
- **Bytes, not Unicode.** Text is a `String` whose characters are bytes; the standard handles are
  in binary mode. Console input is read from file descriptor 0 a byte at a time with the C
  library's `read`, as the C engine does, so no input waits in a buffer another reader cannot see.
- **Control flow.** C's `longjmp` back to the top level is the `RunErrorJump` exception, caught
  where C calls `setjmp`; `exit()` is `exitSpim`.
- `-Wall -Werror`, a type signature on every top-level binding. Only libraries that ship with GHC
  (base, array, bytestring, directory, filepath, haskeline, mtl); the C library's `read`, `write`,
  `open`, `close`, `poll`, `strerror` and `environ` through the FFI.
