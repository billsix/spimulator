# Add a `.dockerignore` (stop baking elpa/ and host build output into the image)

**Status:** proposed — needs go-ahead. Created 2026-11-08 (William Emerison Six <billsix@gmail.com>).
**Priority:** 3
**Difficulty:** 2

## BLUF

The `Dockerfile` copies directories from a context with no `.dockerignore`:
- `COPY entrypoint/dotfiles/ /root/` bakes the 18 MB vendored `.emacs.d/elpa`, which `make shell`'s
  mount then hides.
- `COPY tree-sitter/ …` brings the host's gitignored, generated `tree-sitter/src/`, which the build
  regenerates anyway (`make` → `tree-sitter generate`).
- `.git` (127 MB) and `builddir/` sit in the context.

Done = a `.dockerignore` excludes them, `make image` succeeds (default flags), and the image has no
`/root/.emacs.d/elpa`.

## Context

- Dockerfile contract, `.dockerignore` bullet: the personal overlay (github.com/billsix/dotfiles
  `.ai-coding-conventions.personal.md`). Model: github.com/billsix/geometricalgebra `.dockerignore`.
- Host-side ignored paths on 2026-11-08: `.crush/`, `builddir/`, `tree-sitter/src/`.
- Separate issue, not this task: the `Dockerfile` (line ~65) still runs `emacs --batch --load
  install-melpa-packages.el` at build, which the Emacs contract forbids (github.com/billsix/runClaudeInContainer
  `tasks/reference/emacs-container-contract.md`, conformance snapshot). Fixing that also removes the
  reason the dotfiles `COPY` ever needed elpa.
- `pgu/` has its own `Dockerfile` and context, and only copies `.clang-format`, so it needs no ignore
  file.
