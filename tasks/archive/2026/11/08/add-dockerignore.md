# Add a `.dockerignore` (stop baking elpa/ and host build output into the image)

Done 2026-11-08 (William Emerison Six <billsix@gmail.com> asked for it), on branch `add-dockerignore`.

## What changed

The new `.dockerignore` excludes:
- `entrypoint/dotfiles/.emacs.d/elpa`: `COPY entrypoint/dotfiles/ /root/` was baking the 18 MB vendored
  package tree, which `make shell`'s mount hides anyway.
- `tree-sitter/src/` and `tree-sitter/node_modules/`: generated on the host and regenerated by the
  image's own `make` in `tree-sitter/`, so `COPY tree-sitter/` no longer brings the host's copies.
- `.git`, `.crush/`, `builddir/`, `*.tar`.

Not changed here: the `Dockerfile` still runs the MELPA install at build when `USE_EMACS=1`, which the
Emacs contract forbids (github.com/billsix/runClaudeInContainer `tasks/emacs-contract-conformance.md`).
`pgu/` has its own context and copies only `.clang-format`, so it got no ignore file.

## Verification (2026-11-08, nested podman, default `make image` flags)

- `make image` succeeded.
- In the image: `spimulator -file helloworld.s` prints "Hello World";
  `/spimulator/tree-sitter/src/parser.c` exists (regenerated by the build);
  `/root/.emacs.d/tree-sitter/libtree-sitter-mips_spim.so` exists; `/root/.emacs.d` has no `elpa/`.
